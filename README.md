碳纤维预制体缝合工艺研发助手。当前交付为 **阶段 4：实验计划、关联记录与 CSV/Excel 导入**。

本项目现位于 `C:\Users\22846\Desktop\碳纤维复合材料缝合技术\Agent`。同级 `CF-Stitch Agent 开发交接包` 保留需求、开发口令和资料档案；后续开发、启动与数据库均以本目录为准。本目录的 `spec`、`sources`、`prompts` 和项目约束为独立副本，应用无需读取交接包目录。

## 第4阶段使用方法

1. 在“实验设计”填写名称并保存计划。C0 未缝合；L1/L2/L3 锁式、C1/C2/C3 链式分别为 5×5、5×10、10×10 mm。保存的是七个待实验组，不创建运行、试样或测量；约20–25 mm背景、条件一致要求和来源保留。重复数、独立制样数、针径、张力、速度和测试方案仍为 null。
2. 下载 `templates/stage4/` 中的空白 CSV 或 Excel 模板。Excel 第一张“数据”表只有58列字段表头，第二张“填写说明”给出中文说明。七组计划 CSV 是计划清单，不能作为测量导入文件。
3. 实际有记录后，一条测量填一行。填写来源编号/引用、来源类别、材料编号与批次/卷号、父预制体、运行及运行段、试样来源、测试方法、加载方向、成型/后处理和原始文件引用。使用 `plan_id/group_label` 关联已保存计划，`control_specimen_id` 关联同来源类别的对照。已知信息冲突会拒绝；未知仍留空并提示。
4. 设定值填 `*_setting_*` 列；实测量单独填 `metric_name/value/unit/measurement_stage`。空值留空，结果为空需填 `missing_reason`；只有真实零才填0。普通指标填 `metric_kind=scalar`，计数率填 `count_rate` 并记录整数分子、正整数分母、观察窗口和单位 `1` 或 `%`；率值须与计数一致。
5. 在“数据管理 → 导入预览”选择研究或演示空间、文件、CSV编码或Excel工作表，核对字段映射、原始行及错误。非空的多余列必须显式忽略；同名自动匹配只建立列映射，不猜测单位。变更文件、映射或空间会使旧预览失效；确认后重新检查，整批事务写入，任何错误全部回滚。重复原件/相同测量不增加记录，同标识不同内容拒绝覆盖。
6. 在“来源统计”和“关联记录”查看各类记录、来源/材料/设备/父预制体/运行/试样/对照/原文件，以及共享依赖组。记录数量与有值测量数量分开；空记录不是训练标签，同试样多项测量也不是多个独立试样。

来源 `experimental_measured`、`literature_measured`、`simulation`、`demo`、`prediction` 分别保存。demo只能进demo空间；其余类别在研究空间内仍分别统计，不能把文献、仿真或预测当成本项目实验。文献均值使用 `aggregation_level=aggregate`，保留 `literature_record_id/reported_sample_size`，不能附个体试样或复制均值来凑重复数。来源身份由用户声明，程序不能证明记录确实来自实验。本阶段没有训练入口，所有依赖组 `training_eligible=false`。

导入的枚举列需要明确填写：`aggregation_level` 为 `individual/aggregate`；未知路径/平台用 `unspecified`；其余可空字段按字段说明留空。不要把 `NA`、带单位数字或公式当数值填入；单位单独填写。材料/方法/方向/单位不自动合并或换算，工艺前设定与工艺后观测通过独立字段及测量阶段保留。

支持 `.csv`（UTF-8或显式GB18030）和静态 `.xlsx`；不支持 `.xls/.xlsm`、公式、宏、合并单元格或外部链接。Excel读取单元格存储值，不解释日期/格式；单次文件上限20 MiB、2万数据行、256列。原始上传字节以SHA-256存入只读表，保存映射、编码、工作表、原行号及解析/规范化版本；外部 `raw_data_ref` 只是引用，未自动读取或核验其文件内容。本阶段不提供覆盖原记录、交互编辑或更正版本工作流；有冲突须先复核身份和原始资料。

计划设备审查只引用用户明确选定且确认适用的人工限制。适用稳定缝合厚度上限6 mm会阻断20–25 mm计划；缺设备/机构资料返回未知。保留原模板，不裁薄试件、不批准执行。建议先由研究者确定低速针线筛查条件，再固定其余条件比较机制和p/s。

## 第3阶段使用方法

1. 在任务工作台记录候选值。新增压实厚度与测量条件、针刺深度、压脚抬升、机械针位间距、上/下层布面张力和线速度，均可留空；这些数值不会从文档自动填入。
2. 在“三场景与审查 → 场景参数卡”查看对应初始窗口、设备设计声明、质量目标及待确认事项。V形沿缝 p=3–10 mm；双层固定 p=10–30 mm、针频100–500针/min、两层布面各20–80 N，分别保留。J型保留5–15针/cm原量及固定头/机器人工位安排。完整卡包含原文、哈希和块位置。
3. 在“条件化计算”填写数值并勾选实际成立的假设。密度仅适用于规则矩形阵列、每格一个穿刺点，且不含额外回针/双针/锁固和有限边界效应。未缝合组 p/s 留空，通过独立分支明示理论密度0。复杂路径返回未知，需真实针位与面积。
4. 在“已存任务审查”选任务。可明确选用一条已保存的人工限制，并确认它适用于本次设备版本和条件；不会默认选择、合并限制或建立整机确认。若使用针刺深度限制检查试件贯穿要求，还需明确勾选“本次要求贯穿当前压实厚度”。

四种状态：`PASS` 通过本条检查；`WARN` 超出来源初始窗口或有条件计算，需审核；`BLOCK` 数值/单位非法或超出适用的人工确认限制；`UNKNOWN` 缺参数、来源、适用假设或设备能力。综合状态按阻断、未知、警告、通过排序；始终只读审查，不把任务改成已批准方案。

理论密度 `N_A=10^6/(p*s)` 输出点/m²：5×5、5×10、10×10、10×20 mm 分别为40000、20000、10000、5000。理想直线同步送料中，p为真实每针前进量且每周期一针时，5 mm×100针/min对应0.5 m/min。10 Hz只有明确每周期一针时才换算为600针/min。它们都是公式结果，不是机器实测或预测。

J型5–15针/cm仅在均匀单排假设下展示约0.667–2 mm，结果仍为警告/待确认，不写成任务默认值、不与D2范围取交集。提升率/损失率要求匹配对照，缺均值、零对照或缺匹配假设不会输出结果；负损失率保留。

确认的稳定缝合厚度上限6 mm不能批准22 mm试件。若只有“针刺深度6 mm”确认，必须明确本次贯穿要求后才能据厚度阻断；压脚抬升、定位重复精度等不能代替厚度能力或最终线迹误差。没有机构、CAD、TCP和夹具资料时可达性/避碰为未知；本阶段也没有运动学或碰撞求解器，资料齐全不代表自动验证。

## 资料读取与使用

在“资料参数”中选择：

- **参数词典**：检索“张力”可分别查看供纱、细纱和布面张力；检索“针距”可区分沿路径 p、行距 s 和机械针位间距。选中记录可看完整条件及对应原句。
- **证据检索**：本地关键词/全文匹配，空格分隔词为 AND，不下载模型或使用云 API。命中结果包含原文、单位所在原句、章节、文件哈希、段落或表格行号；未命中明确显示“未找到证据”。
- **来源审查**：查看本次读取、文件身份与未解析内容；按版本和块 ID 定位，如 `D2:t002:r002`。历史版本单独保存，旧引用不会被自动改成新文件哈希。
- **待确认**：J 型梁 5–15 针/cm、双层 5/6 mm、链式与双线自锁、机械间距 100/120/200 mm、摆动跨距、无底线自锁机构，均保留各方原文和 pending 状态。
- **人工确认版本**：显式填写并存档单项人工限制，来源声明仍保持 `source_only / advisory`。

原件按以下优先级只读查找：项目 `sources/originals/`，然后上一级 `碳纤维/`。支持 manifest 中的文件名和去掉末尾 `(2)` 的本地文件名。两处都没有原件时，才使用 `sources/extracted/D1_text_blocks.json` / `D2_text_blocks.json` 后备；找到但损坏的原件会报告错误，不悄悄改用旧 JSON。

读取使用 Python 标准库 ZIP/XML，不执行宏、域指令、文档中的命令或外部关系。只实现主文档正文与表格，保留空段的段落计数、物理单元格及表格行位置。图片、文本框、嵌入对象、页眉页脚等未解析内容会标记；没有 OCR、PDF 解析或页码渲染验证。章节由大纲或编号标题识别，推断状态单独保存。段落/行 ID 比页码提示更适合作为引用锚点。

D2 的针距 **3–15 mm**、行距 **5–20 mm**、供纱 **0.5–10 N**、细纱 **0.1–3 N**、针径 **0.6–2.0 mm**、起步针频 **10–100 针/min** 保持各自的适用条件。薄件 1–5 mm / 厚件 10–30 mm 是示例，不推断 5–10 mm 非法。初始窗口、设计规格、质量目标、人工确认限制、实测值、公式结果、模型预测分别分类；公式计算不生成实测记录或模型输出。

## 存储与来源

默认数据库为 `data/cf_stitch.sqlite3`，首次打开界面时建立。SQLite **v3** 支持 v1/v2 原地事务迁移，保留已有任务、种子、来源快照、证据和确认记录；新增计划、实验实体、对照关系、原始文件、导入批次和测量关联。新实验表及来源、证据和确认记录禁止更新/删除；同一快照重复导入不会增加记录，种子变化或同一快照证据变化会拒绝静默覆盖。新文件哈希形成新版本，相同文件换读取位置形成独立取证快照。保存前经过 Pydantic 与关联校验，真实与演示空间分开；不提供默认演示数据。

种子保持其原始清单版本；原件读取身份另外记录。文件身份核验不代表设备能力已验证：

- D2 实际原件与清单哈希一致；用作参数与试验设计依据。
- D1 实际原件 SHA-256 为 `7ad8d0cd20914c20a708544ebbf4e93ad676b8adc843c3fecc5e0fccd61b51a9`，清单为 `f97ccd33c4afa780aa76ec441c5d8454e6229cc8b6addd4996f1b9812f04853b`。255 个非空正文段落一致，但不能认定整个文件同一版本。检索优先实际原件；旧种子引用仍定位到清单版本的 JSON，并提示其身份未经原件验证。
- 工程图、图片文字与尺寸未核验。来源初始窗口、设计规格和设计目标都不是实测结果、已确认硬限或已知最优值。

七组模板是约 20–25 mm 预制体的待实验方案，结果为空，不能当成七条训练样本，也不能直接批准在最高设计深度 6 mm 的设备执行。完整来源未决问题见 `docs/SOURCE_AUDIT.md`。

`.gitignore` 排除独立环境、密钥、本地数据库、原始 DOCX、正文抽取、实验数据和模型文件。没有初始化 Git、提交或上传；如未来自行发布，仍须审查规格文件中是否含私有信息。

```powershell
$testOutput = 'artifacts/pytest-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
& '.\.venv\Scripts\python.exe' -X utf8 -m pytest -q --basetemp $testOutput
```

启动测试会在空闲本地端口短暂启动一个专用 Streamlit 进程，读取健康检查与首页后只停止该测试进程。AppTest 使用隔离数据库，不把测试草案写进默认数据库。AppTest 不是浏览器交互测试；本阶段实际测试与未测项以 `docs/PROGRESS.md` 为准。

实现时核对的官方资料：[Streamlit 配置](https://docs.streamlit.io/develop/api-reference/configuration/config.toml)、[AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest)。
