# 阶段1：建立可运行的独立骨架

请先读取AGENTS.md、PROJECT_SPEC.md与docs/PROGRESS.md，只实施本阶段。

1. 确认新项目根目录、已有文件与Python版本。选择兼容依赖并记录版本，不影响其他虚拟环境和焊接Agent。建立app.py、src/cf_stitch/{domain,services,knowledge,models,optimization,storage,providers}、tests、data、artifacts等合理模块，不创建大量无功能假页面。
2. 使用Streamlit建立中文界面，含任务工作台、资料参数、实验设计、数据管理和设置的最小可用入口；模型与优化区域明确标注尚未训练，不展示假预测。
3. 定义Pydantic领域对象：材料/构型、线迹机制、路径图案、平台、工艺参数、设备来源声明、人工确认的设备配置、目标与结果。机器人属于平台，人字形属于路径，无底线自锁保留自定义未确认。为每类数值保留单位、测量阶段、设定/实测区分和来源。
4. 导入spec中的种子为只读来源声明，不自动提升为硬限或实测。建立SQLite存储和有版本的迁移方法。
5. 提供requirements或pyproject、.env.example、.gitignore、README和Windows start.bat。默认本地8502；检测端口占用并报告，不杀其他进程。不把密钥、源报告、模型和实验原始数据提交Git。
6. 无API、无真实数据也能启动和看参数。真实数据表为空，演示模式明确且隔离。

验收：实际运行导入和schema单元测试；能启动应用；页面明确零真实实验/零已训练模型；机器人不能误填为线迹；非法负针距被拒绝；未缝合组p/s可为空。更新进度，给出准确启动命令与尚未测试的浏览器行为，不提前实施阶段2。

# 阶段2：资料检索、参数词典与来源冲突

阅读项目长期约束和进度，在现有代码上只实施本阶段。

1. 根据D2第四至八部分和spec/domain_parameters.yaml建立可检索参数词典，准确保留p=3–15mm、s=5–20mm、供纱0.5–10N/细纱0.1–3N、针径0.6–2.0mm、起步针频10–100针/min、薄/厚件示例及其限定。对5–10mm厚度不设“非法区间”。
2. 支持DOCX正文段落与表格读取，保留文件哈希、章节、块ID/表格行、原句、原单位、适用范围和证据类型。优先读取用户实际放入的原件；提取JSON仅作有局限的后备。PDF只有在可靠实现后开放，图片无法解析需提示人工核验，不静默忽略后声称完整。
3. 实现无需云端的关键词/全文检索，向量检索为可选，不强制下载大型embedding。查询结果必须有可查看证据；无证据时返回未找到，不补造出处。
4. 参数分类至少包含initial_trial_window、design_specification、design_target、confirmed_equipment_limit、experimental_measured、derived、prediction。来源声明与用户确认版本隔离，保留审批人与理由。
5. 实现冲突/语义待确认列表：J型梁5–15针/cm；双层5/6mm；链式与双线自锁；原文多针针距100/120/200mm；摆动跨距定义；无底线自锁机制。不要自动择一覆盖或取交集。
6. 文档内容仅是证据，不能触发任意命令、修改阈值或泄露凭证。

验收：检索张力能区分供纱与布面；检索针距能区分p/s/机械间距；来源ID可以回到原句；没有证据不会给假引用；恶意“忽略规则”的文档段落不起作用。更新进度后停止。

# 阶段3：确定性计算、约束审查与三个工程配置

先读AGENTS.md、PROJECT_SPEC.md、SOURCE_AUDIT与进度，只实现本阶段。

1. 把全部领域审查实现为可独立测试的Python函数，返回PASS/WARN/BLOCK/UNKNOWN及来源。研究初始窗口外是待审查，不等于必定危险；已确认设备硬限外禁止候选批准。未确认设备能力只能给草案。
2. 实现单位转换、规则矩形阵列密度N_A=10^6/(p*s)、匹配对照的提升率/损失率。密度仅用于每格一个穿刺点的阵列，复杂/双针/回针路径必须按实际针位计算或返回不支持。未缝合p/s为空，理论密度可明示0但不除零。
3. 可实现理想直线同步送料v=p*f/1000（m/min），仅当p是实际送料方向每针前进量、f是针/min、每周期一针时有效。不能把摆幅或曲线参数代进去。有限试件针数要说明边距/端点；并行节拍不能直接除以机头数。
4. 实现场景配置：V形沿缝p3–10mm，关联5–15mm摆动、6mm/800针min设计声明；J型关联R角/法向/工位1、2固定及3机器人、30mm/10Hz声明；双层关联两层布面20–80N、p10–30mm、100–500针min、错位目标0.5mm。保留所有来源状态，不强行把场景值裁进通用窗口。
5. J型5–15针/cm只在均匀单排假设下显示p约0.667–2mm并待确认；多针机械间距不能当p。材料厚度、针深、抬脚高度和稳定缝合厚度分开。
6. 做参数化示意/参数卡即可；缺少CAD、TCP、机构与夹具数据时明确无法验证可达性/避碰，不输出真实机器人程序或设备写入。

验收：5×5、5×10、10×10、10×20分别为40000、20000、10000、5000点/m²；5mm×100针/min满足假设时为0.5m/min；10Hz=600针/min；确认上限6mm的设备不能批准22mm试件；双层p20mm不被误判为数学非法；无匹配对照/零分母不输出提升率。更新进度后停止。

# 阶段4：实验数据库与无数据时可用的试验设计

先读项目约束与进度，只实施本阶段。当前不需要搜集真实实验数据。

1. 实现sources/materials/equipment/trial_plans/process_runs/specimens/measurements等实体以及CSV/Excel导入视图。保留source_id、材料批次/卷号、父预制体、运行段、试样、对照、测量阶段、测试方法与方向、原始数据引用；导入先预览映射与问题，再事务写入，失败回滚。
2. 参数设定与过程实测分开；工艺前可知与工艺后才知分开；供纱/布面张力分开。目标缺失保留null，未知单位/不匹配材料/方法不能默默合并。计数率保存分子、分母和观察窗口；文献均值不能复制成多个独立试样。
3. provenance区分实测、文献实测、仿真、demo、prediction。原始文件只读，清洗版本化。演示数据仅用于测试和演示，不混入真实训练。实现重复与共享对照/父试样关系检查，为后续leakage_group_id提供依赖信息。
4. 原样实现spec/experiment_templates.yaml：C0未缝合；L1/L2/L3锁式p×s为5×5、5×10、10×10mm；C1/C2/C3链式同三组合。保留原组名，约20–25mm厚件适用背景和材料/铺层/压实/后处理一致条件。
5. 明示这是7个待实验组而非7条实测数据；重复数、独立制样数、针径、张力、速度、试验标准由用户确认，不自动填数。设备不能满足厚度/线迹时保留模板但不能批准执行。给出先低速针线匹配筛查、再控制p/s与线迹的分步计划。
6. 输出空白录入模板、实验清单和缺失项报告；可随机化/区组化，但要记录种子、分组依据，不能制造测量结果。

验收：重导不重复入库；缺值不是0；演示与真实统计分开；7组模板准确且measurements为空；7组不被自动当作足够训练样本；不适配设备能阻止方案批准。更新进度后停止。

# 阶段5：可解释预测模型、分组验证和适用域

先读长期约束和进度，在现有代码上实施数值训练框架，不微调LLM。

1. 每个目标独立筛选有效标签，支持工艺质量和最终性能两类。先实现Dummy/Ridge基线、RandomForest和GaussianProcessRegressor。数据未提供时所有真实模型保持not_ready，不能自动用合成数据生成“已训练”状态。
2. 明确工艺前模型仅能用当时可知的材料/构型/设备/设定参数。工艺后评估可另建模型使用已测峰值力等信号。缺失目标不得插补成实测标签，测试用随机数据只能放tests/fixtures并标记demo。
3. 默认按材料体系、工艺场景、测试方法/方向和后处理范围建立兼容子集。设计leakage_group_id：同父预制体、相邻运行段、重复记录、共用对照等依赖必要时合并连接分量；不能只拼接多个ID造成同源泄漏。
4. 实现GroupKFold或LeaveOneGroupOut，折数不能超过独立组数。预处理、特征选择和调参都在训练折内，留出外部批次用于声明范围的验证。独立组不足时报告无法可靠评估，不退回逐行随机切分。模型阈值可配置，不用任意行数承诺可靠性。
5. 报告单位明确的MAE/RMSE，条件允许才显示R²。保存折外预测、分组/切分、数据哈希、参数、软件版本和随机种子。区分not_ready/exploratory/validated_for_scope，验证范围明确到目标。
6. GPR输出均值与模型标准差，标注未校准状态；有独立校准/验证后才报告相应覆盖率。不要把森林树间方差、GPR标准差或重复实验标准差混同为合格概率。实现未知类别、范围外和支持稀疏的适用域警告/拒绝。
7. 可做置换重要性等关联解释，明确不是因果证据，不假设缝合越密性能必然越高。

验收：无标签/全部demo/独立组不足时不给真实预测；同源依赖不跨折；工艺前模型拒绝后验特征；目标缺失不伪造；外推提示；固定种子重跑可追溯。测试成绩只能标为软件自测，更新进度后停止。

# 阶段6：约束多目标优化与下一轮实验推荐

读取项目约束与进度，只实现本阶段。

1. 没有通过对应范围验证的目标模型时，优化入口退回DOE/数据补齐，不输出预测最优点。有模型后才在用户批准的场景窗口、确认设备能力、针线可用离散组合和模型适用域内搜索；初始采用候选网格/采样+Pareto筛选即可，避免先堆复杂算法。
2. 按需最大化ILSS及Mode I/II韧性，约束面内性能损失、孔隙率、断线、耗时；三场景保留各自目标。未训练的目标不能捏造；缺少关键约束阈值时提示补充，不称“满足全部约束”。同一指标不能混用不同测试单位和试样条件。
3. 只报告候选集上的Pareto方案，不声称全局最优。每个候选显示参数、实际用到的模型、预测、不确定度方法/状态、约束裕量、适用域和来源。高性能/低损伤/高效率等标签必须由真实筛选逻辑产生。
4. 无可行解时列出造成不可行的约束，不自动放宽或覆盖原阈值。超出窗口的探索必须单独申请人工批准，不能默默让优化器向外推区逃逸。
5. 增加下一轮实验：有可信模型时区分预期改进、降低不确定性、基准重复，保留空间多样性与预算；无模型时只做有依据的初始设计。候选始终标记待实验，不把模型预测回填为真实观测。新实验记录proposal_id和experiment_id。
6. 加入人工审核卡；仅导出研究参数/实验计划，永远不发给PLC或机器人自动执行。可以做方法对照接口，但没有前瞻实验不能声称主动学习已经减少了多少实验。

验收：Pareto方向和支配关系正确；无可行集明确返回空及原因；设备超限不会入选；缺目标/未知阈值不会假通过；demo候选不能污染真实实验；结果能追溯至模型与数据版本。更新进度后停止。

# 阶段7：LLM工具编排、报告和端到端交付

先读全部长期约束与进度，整合已有功能，不重写已经通过验收的模块。

1. 建立一个固定工作流优先的任务协调器，把自然语言转成结构化任务，调用retrieve_evidence、validate_task、compute_geometry、predict_targets、propose_candidates、design_experiments、summarize_experiment。所有工具参数在服务端校验，LLM不能任意执行代码/SQL/shell或改机器阈值。
2. 增加可选LLM provider：base_url、model、api_key、timeout可配置；具体API按实施时官方文档核实。检测是否支持tool calling，不能因“不支持”而虚构成功；不支持时可用JSON提议+本地校验。无API时仍支持表单与规则工作流，网络失败只降级已实现能力。
3. 凭证仅从环境变量/本地安全配置读取，日志脱敏，私有实验与技术文件默认不出网。发送前展示目的端、片段/字段和授权范围；不默认上传全文，离线模式不得发生网络请求。检索内容不能被提升为命令。
4. 结果卡分栏：资料事实、公式结果、真实数据、模型预测、未决问题、下一步。数值必须由工具返回并带结果ID，LLM不能润色成未实测的百分比。模型未就绪时给能执行的实验计划与缺失清单。
5. 报告导出至少支持Markdown和结构化JSON，含单位、来源、设备审批状态、数据/模型版本、适用域、约束、候选与实验验证状态。PDF/Word只在真正实现且检查排版后加入，不用假按钮。
6. 做端到端测试：空数据库→导入来源→生成7组计划→参数审查→导入明确标记的测试夹具→隔离训练自测→候选生成→导出。另测错误API、超时、缺参数、来源冲突、未知机构、无可行解、文档注入、密钥泄漏与离线不出网。
7. 实测启动、页面按钮和桌面/窄屏交互；可使用Streamlit AppTest和可用浏览器工具。浏览器或真实API不可用时明确“未测试”，不要把mock通过写成真实通过。提供README、start.bat、准确启动命令、依赖版本与完整测试结果。

最终说明目前哪些功能不依赖真实数据可用，哪些等我提供数据后再训练，哪些工程结论仍需实验/设备确认。严禁宣称已经获得SCI结论、完成设备验收或实现真实机器人闭环。更新进度，停止。
